# 猫棋（CatChess）游戏设计文档

> 微信小程序 + 网页双端 | 100 关 | 6×6 → 20×20 | 难度 1~100 打分

## 1. 核心规则（2026-09-30 经 taevas 确认）

N×N 棋盘上放 **N 只猫**：

1. **行列规则**：每行恰好 1 只猫；每列恰好 1 只猫。
2. **色块规则**：每一块相连的同色区域（连通色块）里**有且只有 1 只猫** ⇒ 区块数恰为 N。
3. **禁邻规则**：任意两只猫不能八向紧贴（横竖斜相邻都不行）。
4. **强制格**：只有 1 格的单色块必须放猫（规则 2 的特例，作为玩家的天然入手点）。
5. **同色必连通**（taevas 确认）：**同一种颜色全盘必定只属于一个连通块** —— 颜色即区块身份，每种颜色 = 一个区块（因此最多用 24 色调色板，区块数 = N ≤ 20 恰好够用）。

一句话：**每行每列每色块各住一只猫，猫与猫不能贴贴。**

每关保证**唯一解**。

## 2. 交互设计（双端一致）

| 手势 | 效果 |
|------|------|
| 单击空格 / 单击 ✕ | 人工标 ✕（无猫猫区笔记）↔ 恢复空白（可撤销） |
| 按住拖动 | 连续人工标 ✕（只作用于空白格） |
| **双击任意格** | **判定猫**：判对 → 固定为猫 🐱；判错 → 系统标 ✕（深红，区别于人工 ✕）且失败 +1 |
| 单击系统 ✕ / 猫 | 无操作（系统判定不受人工标记影响） |
| 失败 2 次 | 本关失败 → 弹失败层（再试一次 / 返回） |

- **胜利判定**：N 只猫全部判定正确（双击判对自动锁定）⇒ 唯一解（引擎保证），弹出庆祝层，解锁下一关。
- **失败判定**：双击判错累计 2 次 ⇒ 本关失败（系统 ✕ + 失败计数，弹失败层）。判定机制下不会出现非法双猫局面（判错立即被系统纠正为 ✕）。
- **进度**：localStorage / wx.Storage（`zmm_won`），第 1 关始终解锁，通关前一关解锁下一关。
- **单步提示 💡（结构化、按类型优先级给步）**：提示引擎对**当前局面**实时分析，按由浅入深的固定顺序给出下一步，并高亮相关格、说明动作（放猫 / 标 X / 检查）：

  | 优先级 | 类型（玩家看到的说法） | 动作 | 人话解释 |
  |--------|------|------|------|
  | 0 | 有冲突 | 检查 | 某排/列/色块已经有猫了，或两只猫贴太近 —— 先收回多放的 |
  | 1 | 无猫猫区排除 | 标 ✕ | 猫住下后，跟它同排、同列、同一色块、紧挨着的格子都不可能再有猫，还没标 ✕ 的提示补上 |
  | 2 | 必须住这 | 放猫 | 只有一格的小色块，猫只能住那 |
  | 3 | 只剩这一格 | 放猫 | 某排/列/色块排除来排除去，能住猫的只剩一格 |
  | 4 | 猫位锁定 | 标 ✕ | 某色块的猫只能住某排/列 → 这排/列其它格子都没猫；某排/列的猫只能住某色块 → 这块其它格子都没猫（k=1 指向） |
  | 4.5 | 猫位锁定（子集） | 标 ✕ | 2~3 个色块的猫只能住同样数量的排/列 → 这几排/列的猫位被它们包了，别的色块在这里的格子都没猫（Hall 子集 k=2..3） |
  | 4.6 | 这格没猫 | 标 ✕ | 假如这格住猫，某排/列/色块就没有格子能住猫了（矛盾）→ 这格肯定没猫 |
  | 5 | 大胆假设 | 放猫 | 推理走不动了，从剩得最少的一排开始猜 |

  （引擎内部类型名：conflict / x-prop / forced / row·col·region-single / point-* / subset / reductio / trial）

  与每关文档的「提示链」（完整推理过程）同源，同一套推理引擎。

## 3. 关卡体系

- **100 关**，规格从小到大：6×6(1-8) → 7×7(9-15) → 8×8(16-22) → … → 19×19(93-99) → 20×20(100)，每种规格约 7~8 关（见 `levels/plan.json`）。
- **主题命名**：小院(6-7) / 街区(8-10) / 公园(11-14) / 城区(15-18) / 猫都(19-20) + 猫名（团子、煤球…）。
- **难度 1~100**：目标难度 = 关卡序号曲线 `round(8+(id-1)*92/99)`，生成时带内匹配（±5）。
- **不重复**：区块布局哈希（size+regions）全局查重；难度分全局唯一。
- 每关一个文档：`docs/levels/L###.md`（色块图 / 解答 / 强制格 / 提示链 / 验收记录）。

## 4. 难度模型（difficulty.js）

```
raw = 尺寸分(0~38) + 逻辑分(4~42) + 强制格分(0~8)
最终 = clamp(校准表(raw), 1, 100)   /* 单调分段校准：100 关 raw 全序排名 → 1..100 */
```

校准表由 `node engine/cli.js recalibrate` 烘焙进 difficulty.js（锚点 = 各关 raw 升序 → 名次），保证：难度分全局唯一（1~100 恰好占满）、单调（raw 越大分越高）、双端复算一致。

- 尺寸分：`(n-6)/14 × 38`，体现搜索空间与视觉负担。
- 逻辑分：提示引擎推理链加权平均（每只猫的平均推理权重 wavg：强制 1 / 唯一候选 2 / 指向排除 4 / 试错 8），`clamp((wavg-1.5)/4.5)×38+4`。需要试错的关明显更难。
- 强制格分：强制格越多越容易（入手点多），`(1-min(1, F×2/n))×8`。

## 5. 生成算法（engine/src/generator.js）

1. **随机合法解**：列排列 + 相邻行列差≥2（随机序回溯）。
2. **分区生长**：每只猫格作种子（区块数=N 天然满足恰好一猫）；部分猫格按难度目标保持单格（强制格）；随机多源 BFS 生长（水平偏置制造条状区块收紧解空间；先占 pass 保证非强制区块≥2格）。
3. **收紧 pass**（可选）：把过大猫区块裁成 2~3 格，剩余并入邻块。
4. **唯一化双引擎**（循环至唯一解）：
   - **边界移动**（首选，不增加强制格）：把替代解的猫格并入「相邻且已含替代解另一只猫」的区块 → 替代解一区块两猫被消灭；
   - **挖格**（兜底，单调收敛）：把目标解猫格挖成单格强制区，原区块剩余碎片并入邻块。
5. **不变量维护**：区块连通修补、意外单格合并（非猫格不允许单格区块）、id 压缩（K=max+1 必须等于 N）、每区块恰好一猫校验。
6. 生成后 validate：唯一解、解与配置一致、连通、强制格⊆解、难度带匹配、哈希查重。

## 6. 双端架构

```
engine/src/           # 核心逻辑（UMD：Node / 浏览器 / 小程序三端同源）
  core.js             #   调色板、贪心着色、放置校验 checkPlacement / isWin
  solver.js           #   求解器（排列 DFS + 恰一猫剪枝 + 随机候选序）
  hint.js             #   提示引擎（人类逻辑链：强制/唯一/指向/试错）
  difficulty.js       #   难度打分
  generator.js        #   关卡生成（Node 专用）
levels/L###.json      # 关卡数据（唯一来源）
web/                  # 网页版（引用 ../engine/src + levels-data.js）
miniprogram/          # 微信小程序（utils/engine/ 与 data/ 由 build 同步）
engine/cli.js         # gen / gen-batch / validate / docs / index / trace / build / accept
```

- `npm run build` 把关卡与引擎同步进小程序；网页直接引用 engine 源文件。
- 交互模型双端同构（见 §2），提示/判负/胜利共用同一引擎。

## 7. 验收流程

1. **引擎验收**：`node engine/cli.js validate --all` 全绿。
2. **网页操作验收**：驱动接口 `window.__zmm`（tap/dragX/load）经真实 pointer 事件按解答操作全部 100 关，验证胜利判定；结果经 `accept-batch` 回写进每关文档。
3. **问题处理**：修复 → 重试 ≤3 次 → `docs/QA.md` 登记。

## 8. 已知设计取舍

- 大棋盘（15+）依靠少量强制格 + 边界移动收敛唯一性；难度主要来自规模与推理链长度，而非强制格数量。
- 颜色语义：每区块独占一色（恒等映射），同色必连通；调色板 24 色 ≥ 最大区块数 20。

## 9. Cocos 动画版（2026-10-01 起，主战场）

- 定位：动画体验版（猫落地弹跳/判错红闪/彩纸/星级弹入），原生小程序版冻结，web 版保持极简。
- 素材：Kenney UI/背景/音效（CC0）+ AI 生成猫（卡通 Q 版，标准见 docs/ASSET_STANDARD.md：一票否决门 + ≥9 打分表）；猫四态缺图时自动降级为变形动画+表情标记。
- 进度：通关存档（星级 3=零猜错零提示）+ 顺序解锁；设置页（音效/重置）；首次启动规则页。
- 流水线：`npm run build-cocos`（引擎/数据同步）→ `build-cocos-web` / `build-cocos-wx`（微信引擎分离，主包≤4MB）→ `cocos-smoke`（headless 驱动 __zmmCocos 验收+截图）。
